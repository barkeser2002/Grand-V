# FiveWeb platform: dedicated servers and trusted resources

Scope of this document: what the web host in `/opt/grand-v/web-host` does today, and what it does not do.

## Dedicated named servers

- Server entries come only from `config/servers.json` (operator-owned). There is no public endpoint that creates a server. `POST /api/servers` answers 405/404.
- The config is validated strictly at startup. Unknown fields, bad ids or names, duplicate ids, duplicate or unknown resource bindings, and malformed JSON abort startup.
- A server entry persists across restarts and across empty rooms. The room behind it is ephemeral: the first join creates a relay room (LobbyStore lobby, host seat), the second join reserves the other seat, and when the last peer leaves the store removes the room. The next join creates a new room.
- Capacity is 2 (one remote replica, the engine's real limit). Nothing claims more.
- At most one room per server exists at a time. Two servers never share a room.
- Joins are synchronous in Node's event loop, so check-and-claim cannot interleave.

HTTP surface:
- `GET /api/servers` returns `{servers:[{id,name,description,connected,reserved,capacity:2,status:'online'|'full',tags,resources:[{name,version}],voice:true,compatibility:'fiveweb-js-v1'}]}`.
- `POST /api/servers/:id/join` with JSON `{nickname}` returns `{lobby,session:{role,credential,expiresAt},launchPath}`. `launchPath` is `/launcher.html?lobby=<relay-room>&server=<server-id>`. The first join is `role: host`, the second is `role: guest`, a third is 409.
- `GET /api/servers/:id/resources` returns public manifests of the resources bound to that server.
- `GET /__resources/:serverId/:resourceName/:file` serves only client files that the manifest lists and that belong to a resource bound to that server.
- Legacy `/api/lobbies` routes are unchanged and still exist for regression.

## Resources (FiveWeb resource system)

This is FiveWeb's own resource format. It is not FXServer compatibility, and no FiveM/FXServer compatibility is claimed.

- Layout: `resources/<name>/fiveweb.resource.json` plus the files it lists.
- Manifest: `{name, version (x.y.z), apiVersion: "fiveweb-js-v1", client: [...], server: [...]}`. Unknown fields are rejected. Client files are `.js` or `.mjs`. Server files are `.mjs` only. Filenames must be flat (no paths).
- Load-time checks: real files only (no symlinks), realpath must stay inside the resource folder, the manifest name must match the folder name.
- Client files are public. Server files are never served over HTTP and their names are not published.
- Server modules are trusted operator code. They are imported in-process at startup. Nothing a player uploads is ever imported, and no request path selects code.
- Node `vm` is not used and is not a sandbox. Do not treat resource code as isolated from the host process.

Server API (`start(api)` / `stop(api)` exported from each server module):
- `api.resource` (name, version), `api.log(msg)`, `api.on(event, fn)` returns an unsubscribe function.
- Events: `server:roomCreated` and `server:join` (payload: serverId, roomId, role). Payloads contain no credentials.
- On stop, every subscription is removed and `stop(api)` is called in reverse order.
- A failing `start` stops what already started and rejects startup.

Client API (`public/resource-client.js`, a classic script injected into game pages):
- Reads `?server=<id>` from the page URL. Without it the client does nothing.
- Fetches the server's manifests, imports each listed client file from the same origin, calls `start(api)`, and calls `stop(api)` on `pagehide`.
- `api` contains: `resource`, `server.id`, `setStatus(text)`, `notify(text)`, `log(msg)`. It has no lobby credential, no network send, and no game natives.

Example: `resources/welcome` shows a status line and a toast in the game through the client API. Its server module logs join events.

## Not done, and limits

- Client-to-server resource events are not implemented. There is no authenticated network event path. Resources only get server-side events generated by the host.
- `server:roomClosed` is not emitted. The relay has no hook for it in this codebase, so server code cannot observe room removal directly.
- Resource server modules are trusted and not sandboxed. Operator code runs with full host privileges.
- The client loader needs `?server=<id>` on the game page URL. The legacy launcher now keeps `server` through launch (`launchUrl` leaves unknown keys alone, and the game whitelist admits `server`). Verified by a real launch-URL test and a real headless Chrome run.
- The game page whitelist admits `server` in addition to `multiplayer`. The loader validates the id (`^[a-z0-9][a-z0-9-]{1,39}$`) before any fetch.
- The original donate, tweet, trade and dialog elements are hidden in the served launcher and game pages by an injected style block. The DOM stays in place. Wallets and donation text are unchanged.
- The browser loader has automated tests: a factory unit suite with fake fetch/importer/DOM, a classic-script bootstrap test in a vm sandbox, and a real headless Chrome run over HTTP.
- Still open: the resource status line sits bottom-left (moved from top-left), but it was not checked against the real voice mic or multiplayer HUD layout in a rendered view. Only computed-style and DOM output were verified.
- Still open: `/branding/grandv-logo.png` references inside original JS and CSS (for example `loading_intro.js`) are not rewritten. Only the served HTML is changed.
- Still open: the launcher-side GPU gate and real game start (WebGL, mic, voice, full multiplayer session) are not verified by this worker. Domain, TURN and GitHub Actions are parent-owned.


## Brand

- Served launcher and game titles, the logo alt text and the icon link read FiveWeb. The visible launcher heading reads "FiveWeb Launcher". Donation, tweet and trade controls (hidden by CSS, DOM kept), GTA names, engine identifiers and storage keys are unchanged. Original files on disk are not modified.
- Brand files are served only from fixed routes: `/__brand/`, `/__lobby/brand/` and `/brand/` each with `fiveweb-logo.png`, `fiveweb-icon.png` and `fiveweb-icon.ico`. Brand routes are optional at startup, so a fixture public dir without `brand/` still loads.
- The lobby page text belongs to the UI worker. The brand tests check only that FiveWeb appears and BarisGrandV and Grand-V do not.
